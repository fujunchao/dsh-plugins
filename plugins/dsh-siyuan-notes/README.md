# dsh-siyuan-notes

DeepSeekRuntime（DSH）Web 插件：在左侧栏加一个入口，打开主面板即可浏览、搜索、编辑自建的
SiYuan Note（思源笔记）文档。思源内核跑在本机或局域网 Docker 里，DSH 只做前端壳。

API token 由 DSH 宿主保管。Markdown 模式调用同源的 `/siyuan/*` 路由；原生模式通过本机隔离网关加载当前思源内核配套的页面。

## 原生编辑器试用

打开文档并保存当前修改后，点击工具栏的 **原生编辑（试用）**。正文由思源自己的 Protyle 编辑器编辑和自动保存，DSH 保留文档入口、分栏、AI 对话和记忆面板。当前已对思源 **3.8.3** 做真实内核与浏览器验证，试用入口限定 3.8.x；其他小版本仍需单独验收。

- **第一次登录**：在内嵌表单输入思源锁屏密码，默认勾选 **记住登录 30 天**。通过思源官方 `rememberMe` 登录后，重启 DSH、重新打开原生编辑器都可以恢复登录。勾选关闭时只保留当前运行会话。验证码由你本人填写。
- **登录保存与失效**：Windows 使用当前用户的 DPAPI 加密保存思源签发的 Cookie（会话凭据），文件位于 `%USERPROFILE%\.dsh\siyuan-native-sessions\`，不单独保存锁屏密码。期限按服务器响应且最长 30 天，不会因每次打开而自动续期；连接地址和 API token 分别隔离。重开时仅用 Cookie 校验，过期或服务端撤销后返回登录页，网络暂时故障则保留记录供重试。其他系统目前仍可登录，但会明确提示无法安全保存到下次运行。
- **忘记登录**：原生编辑器顶部的“忘记登录”清除当前连接在本机保存的凭据，下次打开需重新登录；当前已打开的文稿仍可继续完成编辑和保存。若记住登录失败，会明确提示，不会显示为已保存。
- **原生编辑**：段落、列表、表格、图片、选区及撤销使用思源原生机制；无需手动 Ctrl+S。内核提供当前版本的前端构建，本插件不带另一套 Protyle 构建。
- **选中提问**：选中文字后点原生编辑区的“引用到 DSH 对话”，或顶部“引用选区到对话”。文字和块 ID 写入 DSH 输入框，由你决定何时发送。`siyuan_note_context` 返回当前文档、当前块 ID、选区及保存待确认状态；原生模式不伪造源码行号。
- **AI 插入**：原有 `siyuan_note_insert_image` 继续使用；新增 `siyuan_note_insert_text` 可以在指定块后或文档末尾新增一个纯文本段落，支持换行，Markdown 标记按文字保留。写前备份、验证目标归属、写后读回确认；原生界面通过实时连接显示新内容。它不替换选区，也不提供整篇覆盖。
- **切回与退出**：点“切回 Markdown”会先确认原生事务，再重新读取正文。切标签、关栏也先确认事务；离开整个笔记面板时，独立内嵌页面保持连接直到保存确认。失败时保留原生文稿，并提供重新确认和明确放弃入口。
- **备份**：进入原生模式前落一份 Markdown 快照，后续编辑使用思源原生历史；AI 插入仍单独执行写前备份。原生模式不执行旧的 Markdown 分块保存流程。

本阶段的边界：原生试用适用于 **DSH 与浏览器在同一台电脑** 的桌面/本机 Web 使用方式；远程浏览器访问 DSH 服务器尚不支持。试用模式不跨 DSH 重启恢复，重开默认回到 Markdown 模式。内嵌视图使用思源内置明暗主题，独立维护布局；自定义主题及其他思源插件的组合尚未验收。原生模式的首行缩进、命令菜单和快捷键遵循思源设置；现有 Markdown 专用工具栏与源码行号大纲不会接管原生正文。真实系统输入法候选窗的手感、自由图片缩放、多窗口长期使用仍需体验验证。

新增宿主模块需要重新加载插件后生效。如果插件管理页显示“当前 profile 的 patch 无法唯一定位这一项”，请在保存其他工作后重启 DSH；仅刷新前端可能已出现按钮，但宿主仍会返回“未知路由：/siyuan/native”。

实施与验收记录见 [`../notes/siyuan-native-implementation-2026-11-09.md`](../notes/siyuan-native-implementation-2026-11-09.md)。

## 功能

- 左侧栏入口 → 主面板（`sidebar.panellist` + `main` 面板槽）。
- **分屏双编辑器**：最多三栏并排，每栏独立打开文档、独立编辑、独立保存（见下文「分屏编辑」）。
- **首行缩进写作模式**：回车即生成缩进两格的新段落，缩进作为真实内容写入思源（见下文「首行缩进」）。
- **图片**：工具栏 **🖼** 选文件、`Ctrl+V` 粘贴截图、把图片拖进编辑区 —— 三个入口都写进思源自己的资源库，
  插入后**立刻**在编辑区显示成图片卡片（缩略图 + 文件名 + 行号 + 改说明/宽度/删除），预览与分栏里也能看到真图（见下文「图片」）。
- **编辑器快捷键与写作体验**：Enter 续行与退出列表、Tab 缩进、思源同款行内格式键位、选中浮条、
  括号引号自动配对、大纲跳行、编辑 / 预览滚动同步、字数统计（见下文「编辑器快捷键与写作体验」）。
- **面板内对话 + 引用提问**：底部保留真正的 DSH 对话框；选中原文一键引用进去提问（见下文「面板内对话」）。
- 笔记本 / 文档树浏览，按标题与内容搜索（`/api/query/sql`）。
- 打开文档读取 kramdown 正文，按块（block）编辑并增量保存，尽量不动其它块的 ID。
- Markdown 模式每次保存前、进入原生模式前、AI 插入前自动落一份快照到 `%USERPROFILE%\.dsh\siyuan-backups\<时间戳>-<docId>.md`。
- 连接设置在面板里直接改（地址 + API token），不需要改配置文件、不用重启 DSH。
- **记住你打开的文档**：退出面板或重开 DSH 后回来，上次打开的文档、分栏和每栏的视图 / 自动保存 / 首行缩进设置都还在（见下文「记住上次的编辑状态」）。
- **长期记忆体**：在思源里维护一个独立笔记本，存跨会话的项目决策、踩过的坑、用户偏好和当前进度。模型用 memory_search / memory_read / memory_write 读写，**写完即生效**；检索结果每行带条目 id，模型可以直接接着读全文；会话起点注入一份 1500 字以内的索引，每轮还会按你刚说的话自动带出相关的两三条（关键词匹配，见下文「长期记忆体」）。
- **记忆面板**：侧栏单独一个入口，按类型、状态、项目筛选，有关键词搜索与「加载更多」，点开看全文、可改归属；最近新记的条目列在最上面，记错了一键撤销；积压的候选单独一块列在最前面（见下文「记忆面板」）。

## 记忆面板

侧栏“记忆体”显示独立的记忆列表，支持类型、项目与状态筛选，展开后可查看正文、来源、依据和任务主题。

- **最近 24 小时新记**：列表最上方单独列出刚生效的条目，自动整理写入的带“自动整理”标记，每条都能一键撤销。记忆写入即生效，所以这里是“事后看一眼、记错就撤”的地方，不需要逐条审批。
- **搜索与分页**：输入关键词只在**已加载**的条目里过滤（不发请求、不搜服务端）；「加载更多」每次续读 200 条，到底显示「已全部加载」，底部常显「已显示 M / N 条」（N 取全库真值）。
- **改归属**：展开条目后可直接改项目 / 工作区（走 `reproject`，带版本校验），并把「距上次确认 N 天」显示出来。
- **本会话已停止记录**：对话里明确说了“不要记录这次对话”，或在面板里暂停过的会话，会在面板顶部列出来，并有“恢复记录”按钮。恢复后此前那句话不再生效，但停止期间的对话不会补录。切换“记录开关”或恢复记录后，这份列表不会消失——服务端回包会把当前被停止的会话一起返回，随时能看到哪些会话停了。
- **候选（推断）**：只有模型自己标为 inferred（推断）的条目会停在候选：它不进常驻索引的条目区，只在“候选（未核实）”摘要里列最多 2 条（预算紧张时可能一条都不列，目录行的候选计数仍是真值）。v10 起面板在列表上方单列「候选（推断）N 条」区块（不再被 200 条窗口藏掉，最老的在前）。点“确认生效”沿用条目自己的项目和范围，不用填任何字段；**同主题的多条候选会分组**，只有组内最新那条给「确认生效（作废其余 N-1 条）」，其余标「将被一并作废」——不会再出现“逐条确认、最后活下来的是最旧那版”。候选缺工作区或项目时，按钮变成“选范围后确认”，先打开确认弹窗选好范围再确认。需要改范围、改正文或合并旧状态时才用“调整范围或正文后确认”。确认一个 state 候选时，同主题的旧有效状态会自动标为“已被取代”。让模型用 stated / verified 把同样的正文再写一次，也会把候选升级为有效，并把候选当时记下的 supersedes 一并兑现。
- **写入恢复**：可检查响应丢失或部分失败的操作，找到唯一落盘块后继续原写入；属性恢复记录可核对完成或恢复旧属性。明确没有落盘的意图凭据需要人工核对后才能解除重试限制。完成凭据仅在保留至少一天且索引确认后清理；v10 起已回滚的凭据超过 24 小时也会被「清理已完成凭据」收走（此前它们永远清不掉）。
- **记录开关**：面板可持久关闭自动整理和模型工具写入，关闭时取消尚未执行的写入；重新开启不补录关闭期间的对话。环境变量关闭具有优先权。
- **有效 / 已取代 / 已撤销**：撤销保留历史，可以恢复。恢复不会自动提升推断的可信度，也不能让同一任务主题出现两个有效状态；取代它的新状态仍有效时须先处理新状态。
- **交接卡**：沿用面板项目与工作区筛选，标明实际范围，只纳入 verified / stated 的有效记忆，state（状态）保留全文中的“下一步/待决”。数量截断会明确说明。详细会话记录仍用 session_search 查。
- **体检**：只在面板里做（不再是模型工具）。最多扫描最近 200 条，返回 complete（是否完整）和 scannedLimit（扫描上限）；截断结果不能当作全库无问题——v8 起不完整时面板顶部有**常驻横幅**，而「取代关系异常」这类依赖全库视图的判断会标「另有未检查项」（返回 `incomplete`），不再把“没查”显示成 0。除重复、疑似矛盾、过期状态、断掉的取代链和可归档条目外，还会给出「同项目多任务状态」统计（`multiStateProjects`：某项目有几个并行任务主题）——这只是**中性统计**，没有任何批量清理入口：一个项目并行几件事是常态，这些状态都会参与召回。v7 的「只保留最新」已在 v8 下线，原因是它会按“同项目不同主题”跨任务批量作废（真实库 10 组 48 条），见契约 v8 §1。
- **查询失败**：连接或 SQL 失败会显示失败。仅缓存可用时标注结果不完整；未命中不能证明从未记录。

概览 GET /siyuan/memory 只代表存储状态。查看指定会话真正的冻结文本、压力、待整理字数和本轮召回，需要加 sessionId 查询参数。面板“重新读取”不会刷新正在使用的会话快照。

## 长期记忆体

当前契约是 2026-11-19 的 v10（见 [契约 v10](../notes/memory-2026-11-19-contract-v10.md)，`memoryContractVersion=10`）。v5 的“写入即生效”“记了能想起来”、v6 的“检索带 id / 参数不再静默 / 候选升级兑现取代 / 召回只认原话”、v7 的“召回索引内补位 / 注入按项目分组”、v8 的“下线主题漂移一键收敛 / 体检不完整可见 / 注入截断补省略号 / distill 如实回报”全部保留；v9 再做五件：①**整句中文检索不再必然 0 命中**（按二元组展开，FTS 按相关度排序，`complete` 反映是否被截断）；②注入的「待办」改名**「当前状态」**，每条 state 多一行 `下一步：…`；③**候选块改到最后分配**，不再挤掉决策与事实的位置；④召回行去掉 `active`、日期缩成 `MM-DD`，连续失败 ≥2 次会显式提示；⑤面板徽标改用 catalog 真值（`300 条 · 仅显示 200`）。v10 收口「攒着没人管」的三处：**同主题候选确认时一并作废**、候选/视图/分页/搜索在面板里真的能看到、**`memory_read` 不再偷偷写库**且对账从 40 次请求降到 1 次；写入回执带上落点。

**记**

- **写入即生效**：memory_write 一次调用直接生效。用户说的记 stated（默认），实际验证过的记 verified（必须给依据），模型自己的猜测记 inferred——只有它会停在候选。
- **更新进度不用查版本**：同一任务主题再写一条 state，旧状态自动标为“已被取代”，同一主题始终只有一条有效状态。主题名的大小写、空格、下划线、连字符差别会被忽略。修正其他类型的旧结论传 supersedes；expectedRevisions 是可选的，传了才校验旧条目没被别人改过。写候选时带的 supersedes 不会丢：之后用 stated / verified 把同一条正文再写一次触发升级时，候选当时记下的取代会一并生效（目标已失效则跳过，目标换了范围会报错而不是悄悄改错）。
- **自动整理直接生效**：未整理的对话累计约 6000 字，或上下文用到 75% 以上时，在轮末自动整理一次，两次之间至少隔 10 分钟；第一轮的寒暄不会触发。整理出的条目直接写成有效记忆，来源标记为 `distill:<会话>`；模型自己标为猜测的才落候选。模型本轮已经自己写过记忆且上下文不紧张时，自动整理让一轮。只在根会话运行，子代理不整理。
- **手动整理**：说“把这次聊的记下来”会调用 memory_distill。它从**最近**的对话往前读还没整理过的内容，一次最多三段、每段 12000 字、每段最多 3 条、每条不超过 400 字。某一条不合格（超长、状态缺三段、项目名是编的）只丢这一条并在结果里说明，其余照常写入；还有没处理到的更早内容时结果会写明，再整理一次可以继续。
- **不重复**：同文重复写入只返回“已存在”。思源入库会改写部分写法（例如 `0.3~1.5s` 里成对的波浪线被存成下标），写入后会读回正文另存一份指纹，所以被改写过的条目同文重写仍能判重；人在思源里改过正文之后，原文不再算同一条。
- **不记录**：只认明确指向本次对话或记忆体的说法，例如“不要记录这次对话”“这段不要记”“别写进记忆体”“don't remember this conversation”，而且只认**你本人直接说的**——团队消息、子代理完成通知、技能目录这类注入内容里出现同样的句子不算（它们可以参与召回与整理，但不能替你关记录）。“登录页不要记住密码”“别保存 cookie”“这个函数别记忆化”“I don't remember…”这类开发用语不会关掉记录。命中后该会话停止自动整理和工具写入，排队写入也会取消，面板里可以看到并恢复。设置 DSH_SIYUAN_MEMORY_RECORDING=off 可全局禁止写入。另外会拒绝具有明确格式的密钥、私钥和密码；这是有限的模式检查，不能识别所有敏感内容。

**想起来**

- **常驻索引**：会话起点注入一次并在会话内保持冻结，1500 字以内（v9 只读复验：真实工作区 1499 字 / 13 条，含 3 行「下一步」）。目录行给出事实 / 决策 / 状态 / 候选计数；下面按“当前状态、偏好、最近决策、踩过的坑与事实”四类列出（state 记的是“做到哪了”，不是待办清单），每类标题只写一次，配额分别是 3、6、4、4 条，当前项目优先，事实里被读过的优先。每个类目内按项目分组：项目名只在组头写一次，条目行两空格缩进、方括号里只留任务主题与（非默认的）可信度，不带条目 id；四类按“待办 → 偏好 → 事实 → 决策”分配位置（待办永远第一，事实优先于决策），单条最多 80 字、放不下时按剩余宽度截断且至少留 50 字。当前状态类的条目在结论行下再带一行 `下一步：…`（取正文里的「- 下一步：」，最多 40 字；写“无”的不占这一行），预算不够时先舍这一行再截断正文。候选不进这四类：候选摘要在四类分完之后才用剩余预算，放得下就 2 条、只够 1 条就 1 条、放不下就不写（目录行的候选计数仍在）。结尾固定保留“未命中不代表从未记录”。首行「当前项目：」最多列 6 个项目，超出写「等 N 个」，**绝不截断单个项目名**（v7 硬切 100 字会把 `dsh-siyuan-notes` 切成 `d`）。
- **被动召回**：每轮按你刚说的话抽关键词，在当前项目和全局的有效记忆里找最相关的最多 3 条，带 id、类型、项目与日期（`MM-DD`，跨年写 `YY-MM-DD`；`active` 不写，只有候选/已取代这类非默认状态才写出来）放进每步提示，本轮内保持不变。取词只认你的原话（运行上下文、技能目录、时间戳这些注入内容不参与）；文件名、函数名这类标识符权重最高，中文按二元组切分，“工作 / 项目 / 文件 / 配置”这类通用词直接丢掉；如果话里带了项目名或任务主题，对应条目会加分。只有“至少命中一个长词”或“总分够高”才召回，纯指代的一句话（“好的，继续”）连查询都不发。召回先取 12 条候选：不在常驻索引里的先排（最多 3 条），不足 3 条时用**已经在索引里**的补齐——那几行会标“索引内”并带 id，不会再因为“已经写在索引里”而整块消失。查询失败不会把这句话记成“已查过”：最多重试 3 次，失败原因可在面板诊断里看到。查询有 1.2 秒超时，思源慢或不可用时直接跳过，不影响对话；连续失败 ≥2 次时每步提示里会有一行说明“本轮可能漏掉相关记忆，需要时用 memory_search 主动查”，成功一次即清零。它是关键词匹配，不是语义检索——库里没有用相近说法记过，就召不回来。
- **变更提醒**：别的会话或面板撤销、取代、新增了适用于当前范围的记忆时，每步提示里会出现一行，带结论首句和 id。提醒保留到本轮结束；如果失效的那条仍列在本会话的冻结索引里，提醒会一直保留，避免模型下一轮又照旧索引引用。外部直接在思源里改动的条目，只核对 memory_read 读过的（最多 20 个，30 秒间隔）；网络失败不当作删除。
- **工具**：memory_search（默认搜当前项目和全局；每行是“id + 类型 · 项目/主题 · 日期 · 可信度 + 结论”，行首的 id 可直接交给 memory_read；query 可以给整句中文——超过 6 字会按二元组展开，也可以空格分词；命中按相关度排序，被 limit 截断时会说明）、memory_read（全文、版本与可信度；关闭记录时**不再累计引用计数**、一次读只写一次批量属性）、memory_write、memory_distill，共 4 个。memory_topics、memory_checkup、memory_confirm、memory_review 已删除。memory_write 的正文参数名是 text（从检索结果照抄 statement 也认）；四个工具都只认自己 schema 里列出的参数，拼错会直接报 invalid_arguments，不再静默忽略。

**存储与边界**

- 记忆存在思源独立笔记本“AI 记忆体”，首次写入时创建；环境变量 DSH_SIYUAN_MEMORY_NOTEBOOK 可更改笔记本名称。四类文档为偏好、事实、决策和状态，一条记忆对应一个块，可以直接在思源里改正文。
- **作用域**：新条目由宿主绑定真实项目根目录，项目自身不会误识别为 lib/test 等子目录。省略项目时使用当前项目，`project=*` 默认仅限当前工作区，明确所有工作区通用时用 `global=true`。同名项目位于不同目录时互相隔离。缺少工作区标识的旧条目可以跨项目检索，但不自动注入，可通过 reproject 路由显式绑定。
- **状态格式**：state 必须有 topic（任务主题），正文包含结论、`- 下一步：`、`- 待决：` 三段。其他主题的状态可以并存。
- **历史数据**：没有确认哈希的旧条目照常有效；状态、事实、决策、偏好的参考周期 30、90、180、365 天只用于面板体检的过期提示。
- **启动等待**：会话创建只触发后台预热，首次装配最多等待 1.5 秒；快照查询使用独立 3 秒请求超时，失败后按 30 秒间隔重试。
- **会话隔离**：快照、压力、写入标记、整理冷却、召回和后台任务均按 session ID 管理；释放会话或切换思源连接后取消旧任务。
- **重试与部分失败**：内核明确拒绝追加后可重试；响应未知时停止重复追加，通过“写入恢复”核对。凭据存于 DSH 目录下 siyuan-memory-receipts，按连接和笔记本隔离，保存指纹、块 ID、类型、项目、主题、来源、依据和属性修改前后的值，不保存记忆正文和连接 token（依据字段可能含内容摘录）。
- **索引延迟**：思源 SQL 索引滞后约两秒，刚写入的条目由写穿缓存顶上（最多 20 条、10 秒）；未同步的状态另存记录，保证同主题的新状态能正确取代它。

当前限制：思源接口没有跨块事务或服务端版本比较交换。插件在单进程内串行修改、写前重读、写后确认并在部分失败时尝试恢复，仍需避免多个独立宿主同时修改同一取代链。会话被直接关闭时，最后一小段不足 6000 字的内容不会被自动整理（宿主销毁会话后不能再调用模型），重要结论可以说一句“记一下”。自动整理直接生效意味着偶尔会记错，靠面板的“最近新记”撤销。被动召回是关键词匹配，不是语义检索；条目用词和提问完全不同就召不回来。最优的那条如果已经在常驻索引里，现在会以一行“索引内”提示出现（带 id、只给 60 字），但不会重复整段正文。同项目并行的多个任务状态只做统计、不做批量清理（v7 的「只保留最新」会跨任务误作废，已在 v8 下线）；注入只给「当前状态」3 个名额、按项目与时间排，久未更新的任务状态可能不上第一屏，要用 memory_search 找。检索仍是关键词（不是语义）：整句中文现在能查了，但换了说法（“崩溃” vs “报错退出”）仍然召不回。另外，候选升级时若模型同时又显式传了 supersedes，目前仍按“同文已存在、未完成所请求的取代”报错；重试时去掉 supersedes 即可——候选里记下的取代会在升级时自动生效。

## 记住上次的编辑状态

每次切换离开面板（或关掉 DSH 再回来），插件会把**当前的编辑布局**记下来，下次进来直接恢复：

- **恢复什么**：每个分栏打开了哪些文档、哪一栏是当前栏、每栏的视图模式（编辑 / 分栏 / 预览）、
  自动保存开关、首行缩进开关，以及每栏正在看的那篇文档（标签页顺序也保留）。
  左侧目录树的**展开状态**也会恢复，并且会自动展开到当前打开的文档所在的层级。
- **不恢复什么**：**编辑器里还没保存的文字**。布局只是「你上次在看哪儿」，不是内容备份；
  未保存的改动请自己按 Ctrl+S。这样做是刻意的——把没保存的草稿当成已保存内容恢复，比不恢复更危险。
- **文档被删了怎么办**：如果某个记住的文档在思源那边已经不存在了，只有那个标签页会被丢掉，
  其余文档照常恢复，不会整片空白。
- **存到哪**：`%USERPROFILE%\.dsh\siyuan-notes-layout.json`（只含文档 ID / 标题 / 路径与界面设置，
  **不含正文，也不含 token**）。想「从干净状态开始」就删掉这个文件。
- **什么时候写**：布局变化后约 0.6 秒写入（防抖），不会每次点击都写盘。

## 分屏编辑

顶部栏右侧的 **◫** 按钮把当前栏拆成两栏，新栏会自动带入当前文档（和思源的「分屏」一致）；
点某一栏的 **⊟** 关掉它。最多三栏。

- **哪一栏在编辑**：当前栏标题条下方有品牌色下划线；在左侧点文档会打开到**当前激活栏**。
  先用鼠标点一下目标栏（或点它的标签页）再点文档，就打开到那一栏。
- **每栏有自己的标签页**：点 ✕ 关闭标签页；同一栏内可开多篇文档切换。标签标题最多显示约 150px。
- **关闭保护**：标签或分栏内有未保存、未确认的修改时，会询问是否放弃；取消后可按 Ctrl+S 保存再关闭。
  正在保存的标签暂不允许关闭。关闭分栏会检查其中所有标签，包括当前未显示的标签。
- **同时改两篇**：两栏各有自己的缓冲区、保存按钮和 Ctrl+S，互不影响。
- **同一篇文档在两栏打开**：允许（方便对照），但保存后**另一栏会亮起黄点并提示
  「另一个面板保存了这篇文档」**，点「重载」同步，避免用旧内容覆盖新内容。
- **每栏各自独立**：视图模式（编辑 / 分栏 / 预览）、自动保存开关、首行缩进开关都是**每一栏自己的**，
  在一栏点这些按钮不会影响另一栏；只有保存按钮和 Ctrl+S 作用在你正在操作的那一栏。
- **拆栏时继承**：新拆出来的那一栏沿用原栏的这三项设置，之后就各管各的。

## 首行缩进（写作模式）

工具栏的 **首行缩进** 按钮默认开启，专为中文长篇写作：

- **回车即新段落**：开着头缩进时按一次回车，直接开始一个**缩进两格**的新段落
  （不用再手敲空格，也不用连按两次回车）。列表、标题、引用、表格、代码块里回车保持原样。
- **第一段也算**：空文档里手敲的第一段不经过回车，所以在敲下第一个字时会自动补上同一对全角空格
  （在此之前只有按过回车的段落才缩进，第一段会一直顶着左边）。只会补在**新起的那一行**上：
  在已有段落里改字不会被动缩进，自己敲了空格的行也不会被覆盖；输入法还在出候选字时不碰缓冲区，
  候选落字之后才补，补上的缩进不计入打字速度。
- **真实内容，不是假象**：缩进会作为真实的两个全角空格（U+3000）写进思源，
  在思源自己的界面、导出、其它 Markdown 工具里都带缩进。
- **一键补全已有段落**：文档里还有没缩进的段落时，工具栏会在 **首行缩进** 旁边多出一个
  **补齐全篇（N 段）** 按钮，点一下给这些正文段落补上缩进（标题、列表、代码块自动跳过），
  文档变为「未保存」，看完预览满意再保存即可。补完这个按钮就消失，说明没有漏的了。
- **开关和动作分开**：**首行缩进** 是开关，只管「以后按回车要不要缩进」；**补齐全篇** 才是
  会改正文的批量动作。开关点下去没有可改的内容时会明确提示（例如「段落本来就没有缩进（开关已关闭）」），
  不会再出现点了没反应的情况。
- **可逆**：开关关掉时会移除文档里已有的首行缩进（只移除插件写进去的那一对全角空格）。
- **不会把你扔回开头**：点开关或「补齐全篇」改写的是整篇段首，但光标按行内位置映射回原处，
  不会跳到文档第 1 行（这一条以前会）。
- **不会翻倍**：思源在导出 kramdown 时会**自动给每个段落加一对** `　　`（这是显示层，
  不存在正文里）。插件读的时候只剥掉这一对，所以你手写的缩进和它互不叠加——
  反复保存也不会越来越深（有专门的回归测试盯着这条）。

预览面板里段落用 CSS `text-indent:2em` 渲染，和思源里看到的观感一致。

## 面板内对话与引用提问

对话区有**两种形态**，顶部栏两个图标按钮切换，同一时刻只用一个（输入状态是按会话唯一的）：

两种形态的标题栏都带 **⟲ 历史对话**（列出会话，点一行切过来；标出「当前」和「正在回复」）
和 **＋ 新开对话**（开一个新会话，并直接在这一栏里聊）。切换只影响这一栏，不会把你从笔记面板带走。


| 按钮 | 形态 | 说明 |
|---|---|---|
| ▥ | **右侧栏**（默认） | 面板右侧多一列，宽 384px，标题栏有 ✕ 可关闭；不吃编辑区行高 |
| ▣ | **悬浮窗** | 浮在面板右下角；**拖标题栏可移动到任意位置**，**拖右下角可缩放**；标题栏 **—** 收起到面板右边缘变成竖排小标签，点它再展开；**✕** 关闭 |

再点一次同一个按钮也会关闭。渲染的是 DSH 自己的 `conversation.content`，所以模型选择、
权限、排队、工具卡片、发送键都和主对话完全一致。

**引用并提问**：选中一段文字，**手边会浮出一个「❝ 引用到对话」操作条**（源码侧和渲染预览侧都支持），点它即可；
原文会以引用块插入对话输入框并带上出处；对话栏没开时会自动打开。

引用的位置按你选中的文本在原文里定位（渲染会去掉标记与缩进，所以是按首个可识别片段回查）：

```
> 摘自《第一章 红鞋的少女》（第 12 行）
> 走在赶往宿舍的路上，杨曦的思绪被一个困扰了他整个下午的问题所占据。
```

**我看得到你在写哪儿**：编辑器会把「打开哪篇文档、光标第几行、选中哪几行」推给宿主，
我每轮都能看到（也能用 `siyuan_note_context` 工具查）。你说「这一段」「这里」时我不用再问你。

> 输入框能显示的前提：内嵌会话必须带 `phase="active"`，否则它只会排在长消息末尾被滚出视野。
>
> 早期版本把对话塞在面板底部，实测有两个问题：挤掉编辑区高度，且会话内容一长，
> 输入框就被挤到可视区域之外。所以改成现在的右侧栏 / 悬浮窗两种形态。

## 安装

由 DSH 的插件管理器安装本目录（`plugin_manager` → `install_bundle`，target 指向本目录）。
安装会做两件事：把包目录链接进 profile，并把 `cordis.patch.yml` 里的一行 insert 追加进 profile 补丁层。

前置：思源内核已启动并可访问（默认 `http://127.0.0.1:6806`）。

## 连接配置

1. 思源里取 token：**思源 → 设置 → 关于 → API token**（未设置 token 的内核可以留空）。
2. DSH 里：左侧栏点 SiYuan Notes → 面板顶部「设置 / 连接」→ 填地址（如
   `http://127.0.0.1:6806`）和 token → 连接。
3. 连接成功后面板会显示内核版本（`/api/system/version`）。

配置优先级：**代码默认值 < `cordis.patch.yml` 里的 config < 面板保存的值**。
面板保存的值写入 `%USERPROFILE%\.dsh\siyuan-notes.json`，因此升级插件不会覆盖用户设置：

```json
{ "baseUrl": "http://127.0.0.1:6806", "token": "…" }
```

> token 以明文存在该文件里（仅当前 Windows 用户可读），和思源自身的 data 目录同一安全级别。
> 介意的话可以把 token 只写进 `cordis.patch.yml`（同样是明文），或让思源不设 token 而只监听内网。

命令行排错（不需要打开 DSH）：

```bash
curl -s -X POST http://127.0.0.1:6806/api/system/version \
  -H "Authorization: Token <token>" -H "Content-Type: application/json" -d '{}'
# {"code":0,"msg":"","data":"3.8.3"}
```

### 行内格式

| `Ctrl+B` | 加粗 `**…**` | 与思源一致 |
| `Ctrl+I` | 斜体 `*…*` | 与思源一致 |
| `Ctrl+U` | 下划线 `<u>…</u>` | 与思源一致 |

### 其它

| 组合键 | 作用 |
| --- | --- |
| `Ctrl+S` | 保存当前文档（**插件自有**；思源没有保存快捷键，它的内核自己落盘，而本面板要走显式保存） |
| `Ctrl+F` | 打开文档内查找（`Enter` / `Shift+Enter` 上下一个匹配，`Esc` 关闭） |
| `Ctrl+E` | 切视图：切到预览，再按一次回分栏 |
| `Tab` / `Shift+Tab` | 对当前行或选中行加减一级缩进（两个空格） |
| `Enter` | 续行 / 结束当前块（见下） |

### Enter 的行为

- **列表、任务、有序列表、引用**：回车续上同一个标记；有序列表自动 +1。光标停在行中间时，标记连同后半行内容一起带到新行。
- **空项回车退出**：列表项 / 任务项 / 引用里只剩标记没有内容时回车，会把标记去掉、结束这个块，也就是退出列表或引用，而不是再续一个空项。
- **标题后回车**：得到普通段落。
- **代码围栏内回车**：只换行，不做任何续行。
- **开着首行缩进时**：普通段落回车直接新起一个缩进两格（两个全角空格 U+3000）的段落，见上文「首行缩进」。

### 选中后的浮动操作条

- **源码侧**选中文字：浮出 6 个格式按钮 `B` / `I` / `U` / `S` / `</>` / `==`，后面跟一个 **❝ 引用到对话**。
- **预览侧**选中文字：只浮出 **❝ 引用到对话**（渲染结果不能直接加标记）。
- **再点一次取消**：按选区两端的标记判定——选区自带标记（选中 `**粗**` 再按 B）、或选区正好夹在标记之间（只选中 `粗`），两种都会被取消。

### 括号引号自动配对

会按键自动配对的开键共 9 个：`(` `[` `【` `《` `“` `"` `'` `` ` `` `（`。

- 有选中文本时，敲这些键是**包裹选区**，不是把选区替换掉。
- 光标已经在闭键或一对标记之前时，是跳过去，不会插出第二份。
- `*` 和 `_` 只在**有选中文本时**参与：选中一段再敲 `*` 会包成 `*选区*`，敲 `_` 会包成 `_选区_`；
  没有选中时完全不拦截输入（`*` 仍是列表标记，`_` 仍是普通字符，都按原样打出来）。
- `~` 不参与按键自动配对（删除线请用 `Ctrl+Shift+S`，或选中后用浮条）。

### 大纲

树面板的「大纲」页签列出当前文档的 `#` ~ `######` 标题（代码围栏内的不算）。点一行，光标跳到该行行首，并把这一行滚到视口中间。

### 编辑 / 预览滚动同步

分栏视图下两侧按**滚动比例**互相跟随：把一侧的滚动位置换算成它可滚动高度的百分比，再套到另一侧。纯编辑或纯预览时不参与同步。

### 状态栏

底部状态栏从左到右：`Markdown`、字数（`{n} 字`，不含空白字符）、中文字数（`中文 {n}`，只数中日韩表意文字）、块数、打字速度、未保存 / 已保存标记，以及最近一次保存的时间。

### 打字速度

状态栏里的 `{n} 字/分`（英文 `{n} cpm`）是**近 1 分钟的滚动速度**：

- **口径是净增字数**：打进去的字算 +，删掉的字算 −。反复改一句话不会虚高，因为删减会扣回去。
- **停手会衰减**：数字按最近 1 分钟内的实际产出计算，停下来几秒就开始回落，一分钟没输入就归零。
- **只统计真人按键**：工具栏操作（加粗、首行缩进、`补齐全篇`）、恢复布局时载入的正文、粘贴，**都不计入**。实现上靠 `beforeinput` 的 `inputType` 判断，并给程序化写入加了抑制标记——否则点一次「补齐全篇」会瞬间刷出上千字/分。
- **每栏独立、跨文档延续**：左右分屏时，每栏有自己的计数器，在左栏打字不会影响右栏的数字。切换文档后同一个计数器继续（它衡量的是「你现在的速度」，不是「这篇文档的速度」），60 秒窗口会自然把旧数据衰减掉。
- **常显**：不打字时显示 `0 字/分`，这样一眼能确认功能在位。速度每秒刷新一次，所以刚打完字最多 1 秒后才看到数字上来。

## 图片

### 插入

三个入口，都会写进**思源自己的资源库**（`assets/`），不是外链：

| 方式 | 操作 |
| --- | --- |
| 选文件 | 工具栏 **🖼** → 选一张或多张图 |
| 粘贴截图 | 在编辑区直接 `Ctrl+V`（截图工具复制后粘进来即可） |
| 拖拽 | 把图片文件拖进编辑区 |

- 插入后**立刻**显示成图片卡片，不用再手动"收成卡片"；光标落在新卡片下方，可以接着写。
- 多张按你选择的顺序依次插入；同一时刻只跑一个上传（按钮显示「上传中…」并置忙）。
- 上传未完成时切换或关闭标签，会停止该批次后续插入并提示；已上传的资源保留在思源中，不会写入别的文档。
- 单张上限 20 MB（浏览器侧先拦，不发请求），宿主侧硬上限 32 MB；超限给明确提示，不会动缓冲区与撤销栈。
- 一批里只要有一张超限，其余正常的仍会继续上传（不会整批中止）。
- 只接管图片文件；拖进来的非图片文件会被忽略（也不会让浏览器把文件路径塞进正文）。

### 卡片上的操作

| 操作 | 行为 |
| --- | --- |
| 改说明 | 写回 `![说明](assets/…)` 的 alt |
| 宽度 原始 / 50% / 100% | 写回 `{: style="width: …" }`（「原始」= 去掉该属性） |
| 显示源码 | 展开成可编辑的 `![…](assets/…)` 原文，手改后重排 |
| 删除 | 独立图片删掉整行；行内图片只删图片语法，保留前后正文，光标落回原位置 |

### 显示

- 独立图片、正文同一行的图片、同一行多张图片都会在编辑区显示成卡片；行内代码与转义的图片示例保留为文字。
  卡片只是显示分段，保存时不会给行内图片额外添加换行或拆开原段落。
- **预览 / 分栏**里的图片走宿主代理 `GET /siyuan/asset?path=…`（由宿主带 token 取回二进制），
  API token 全程不进浏览器。这一条是必须的：未鉴权的请求从内核拿不到图（裸请求 401、浏览器式请求会被
  302 到 `/check-auth`），直接 `<img src="…/assets/x.png">` 只会是一张破图。
- 宽度按 markdown 里的 `{: style="width: …" }` 渲染；只认 `width` / `max-width` 且值必须是
  `px`/`%`/`em`/`rem`，IAL 里的其它属性一律不进 HTML。
- 图取不到时显示「图未找到」占位并保留说明文字；加载成功时隐藏该提示，更换有效资源后恢复图片。
- 正文里出现"像图片但还不是卡片"的行时，工具栏会多出一个 **🖼↻ 重排** 按钮：打字**不会**自动把一行
  收成卡片（那会吃掉光标），手写完一行图片语法后点它一下即可。

### 保存

- 图片语法仍是原块 Markdown 里的 `![说明](assets/…)`，沿用块级保存；
  独立图片与正文中的行内图片都按原文写回，思源可直接识别为图片。
- 删除图片不会回收 `assets/` 里的文件（交给思源的"未引用资源"清理）。
- 分辨率/格式由思源原样保存；插件不改写图片字节，也不做压缩或转码。

### 让 AI 帮你插图

面板里能插的，模型也能插：装好插件后多了一个工具 `siyuan_note_insert_image`。

| 参数 | 含义 |
| --- | --- |
| `source.kind = "path"` | 读 DSH 主机上的本地图片文件（png/jpg/jpeg/gif/webp/bmp/svg，≤20 MB），先上传到思源资源库再插入 |
| `source.kind = "asset"` | 直接引用资源库里已有的图片（如 `assets/xxx.png`），不重复上传 |
| `doc`（可省） | 目标文档 id 或 hpath；省略时用**你当前在面板里打开的那篇** |
| `after`（可省） | 锚点：块 id，或一段只出现在一个块里的原文；图片插到它之后。省略则追加到文档末尾 |
| `alt` / `width`（可省） | 图片说明；宽度（像素数字或百分比） |

- 返回新块 id、资源路径与最终 markdown，便于复核。
- 写前验证目标是文档、锚点属于目标文档。写后读取独立图片块并核对所属文档及相邻块，确认成功才返回成功；
  最多 8 次校验、间隔 250 毫秒，校验阶段不会重放写入。未确认时返回块 ID，先检查文档再决定下一步。
- 写入前自动落一份快照到 `%USERPROFILE%\.dsh\siyuan-backups`，和手动保存用同一套回滚材料。
- 它**只插入**：不删除、不覆盖任何已有内容，也不提供批量操作。
- 锚点定位走文档正文（不查 `blocks` 索引表）—— 实测索引在大库里要 3.5 秒才跟得上，而正文立即可读，
  所以"刚建好的文档立刻插图"也能插进去。

> 与面板的关系：AI 插图后，若你正在面板里编辑同一篇文档，**保存时会看到「文档已被外部修改」的提示条**，
> 默认动作是「重新读取」。这是刻意的闸门——没有它，面板会把 AI 刚插进去的图当成"多余块"删掉。

## 编辑与保存模型

- **读取**：`POST /siyuan/api` 转发 `/api/block/getBlockKramdown`（或 `/api/filetree/getDoc`），拿到正文。
- **保存**：先 `POST /siyuan/backup` 落快照，再逐块 `POST /siyuan/api` → `/api/block/updateBlock`
  只提交**改动过的块**，未改动的块保持原 ID 与属性，思维导图 / 引用 / 书签通常不会断
  （例外：块内含空行的文档，见「已知限制」）。
  备份失败会停止写入并显示错误；“读取失败后明确跳过检测”仍是独立的一次性选择。
- **保存前的外部改动闸门**：写之前会重读一次文档，和「上次保存点」按**块级文本**比对
  （不是比原始 kramdown —— 尾随空行、两连空行这类版面差异内核读回时本来就和缓冲区不一样，
  按原文比会每次保存都误报）。不一致就停手，浮出提示条：
  - **文档已被外部修改**（AI 插图或思源端改过）→ `[重新读取]` / `[仍要保存（覆盖）]`；
    **自动保存在此期间暂停**，覆盖必须你自己点，插件不会替你选。
  - **无法确认文档状态**（读失败，例如网络抖动）→ 不写，给 `[重试保存]` / `[仍要保存（跳过检测）]`。
    读失败时连备份都拿不到，所以默认不盲写。
  已读取的空文档也是有效基线：外部新增正文或图片同样会触发冲突保护。
- **差异算法**：编辑前后各切成顶层块，用 LCS 求出「保留 / 改写 / 新增 / 删除」四类操作；
  一段「删了旧块又加了新块」会被合并成一次 `updateBlock`（改写），因此整篇重写也不会
  把块 ID 全换掉。改动最少的块不做任何请求。
- **图片块与普通块同一条路径**：插图走 `insertBlock`（新块），卡片上改说明/宽度走 `updateBlock`（同一个块 ID），
  删除整行走 `deleteBlock`。插件不写块属性、不动 `assets/` 里的文件，所以图片的尺寸等属性不会被它覆盖。
- **写入后校验**：内核的读模型比写操作晚一拍，所以保存后会轮询重读，直到读回内容与提交
  内容一致（最多约 1.5 秒）；始终不一致则保留原文并提示，**不会**改用整篇覆盖。
  校验不一致或读取失败均保留“未保存/未确认”状态并暂停自动保存。手动重试会先确认上次写入是否已经落盘，
  已经落盘的新增块不会重复插入；若只落盘一部分，则先提示差异，由用户决定是否以当前磁盘内容为基线继续保存。
- **保存不重排光标**：保存只提交文本，**不会**把内核读回的内容套回编辑框。读回的文本与你在看的
  只可能差在空行上（末尾空行没有对应块，连续空行会并成一个），而把值换掉正是「光标停在空行时
  被弹回上一段末尾」的原因。缓冲区保持原样，只把「刚写进去的那份文本」记为保存点；
  保存期间你继续打的字也不会被这次保存的结果覆盖。
- **自动保存是静默的**：状态栏的「已保存 / 未保存 + 时间」就是回执；提示条改成浮层，
  出现和消失都不占布局高度，工具栏的「保存 / 保存中…」按钮宽度也固定，
  所以自动保存时编辑区不会上下跳一下。
- **绝不整篇覆盖**：`updateBlock(docId, …)` 会重建全部子块 ID，并静默删掉别的客户端
  中途追加的块，因此本插件不调用它。
- **撤销**：`~/.dsh/siyuan-backups` 里的快照就是回滚材料，文件名含时间戳与 docId。

## 已知限制

以下编辑核心限制针对 Markdown 模式；原生试用的适用范围见文首。

- 分屏上限为三栏；栏宽固定等分，不能拖动分隔条（思源可以）。

- 保存粒度是「顶层块」：在一个块内部改字仍然是一次 `updateBlock`，块 ID 不变；
  但把一段文字从 A 块移到 B 块时，内核会视为改写两块。
- **块内含空行的文档，改字保存时这些块的 ID 会变**：有些顶层块自身就含空行，典型是
  「列表项 + 空行 + 缩进子项」这种写法。这类文档改动任意一个字再保存时，这些块会被重构——
  内容不会丢，但块 ID 会变，指向它们的引用 / 书签会失效。只打开不编辑仍然是零写入。
  这是存量问题，**已登记为后续修复项**。缓解：保存前会自动落一份快照到
  `%USERPROFILE%\.dsh\siyuan-backups`，建议先看预览确认无误再保存。
- 表格读回时列宽/对齐会被规范化（`|列1|列2|`、`| -----|`），这是内核的序列化结果，
  不是插件的改写；再次保存不会反复变化。
- 快照是纯 Markdown 文本，不含块属性 / 自定义属性 / 资源文件，回滚需要手工粘贴。
- 同一篇文档被思源端同时编辑时，后写入者覆盖前者（无冲突合并）。
- 只支持 http / https；不支持需要登录页的思源反代（请用 API token 方案）。
- 思源要求 token 时，DSH 每次请求都会带上；不要把插件暴露到公网后仍留空 token。

编辑器侧的缺口：

- `Tab` 在代码块里也会被当成缩进（两个空格），不会插入真正的制表符。
- 表格单元格之间不能用 `Tab` 跳转，也不能用 `Tab` 在单元格里插入制表符。
- 没有斜杠命令菜单、没有块拖拽、没有实时协同；也不是真正的所见即所得，预览是按块做的近似渲染。
- **没有撤销粒度控制**：撤销走浏览器原生栈，一次程序化编辑（格式按钮、缩进、大纲跳转、首行缩进批量补全）算一步。若运行环境没有 `execCommand`，这些编辑会退化成直接赋值，此时原生撤销历史会丢失（文字仍能正常保存）。
- **编辑 / 预览按滚动比例双向跟随是插件自创行为**：思源里编辑与预览是互斥视图，没有可对照的实现；这套同步没有做过观感验证。
- **选区格式的取消判定与思源不同**：思源要求选区内**全部**文本都带该格式才取消，本插件按选区两端的标记判定，所以部分格式的选区表现会不一致。
- 文档内查找只在编辑 / 分栏视图出现（纯预览下不显示查找条）；它是纯文本、大小写不敏感、最多 1000 个匹配，只把命中的文字选中并滚到视口中间，不做全文高亮。

图片相关的限制（编辑区已改为「文本段 + 图片卡片」，以下是这套结构的固有取舍）：

- **`Ctrl+Z` 只作用于当前段**：跨段撤销不覆盖另一段里的改动。这是分段编辑的代价——换来的是图片在编辑区原位可见。
  浏览器原生撤销栈的作用域就是单个 textarea，做全篇撤销需要自研快照栈，列为后续专项。
- **「重排卡片」是手写图片语法后收图的唯一入口**：打字不会自动收（否则键入 `![](` 的瞬间该行会跳成卡片并吃掉光标）。
- **图片卡片不支持自由缩放与拖动排序**：只有「原始 / 50% / 100%」三档宽度；更细的尺寸请在思源里调（插件不会覆盖块属性）。
- **删除图片不回收资源文件**：`assets/` 里的文件交给思源的「未引用资源」清理；插件不删任何资源。
- **只上传到工作空间根 `assets/`**：与现有库一致；不支持把图片存进笔记本级 assets 目录。
- **编辑区滚动从「整篇一次」变成「容器滚动 + 段内自适应高度」**：编辑↔预览的滚动同步按行锚点映射，
  锚点缺失时退回按比例滚动，观感需以实际使用为准。
- **图片在编辑区是卡片、在 markdown 里是唯一真值**：卡片上的操作（改说明/宽度/删除）都会真改文本，
  点「显示源码」可随时核对。
- **外部改动闸门的两条边界**：① **从没被读入/保存过的新草稿没有基线，不做检测** —— 首次保存前若被
  外部插入内容，仍会被覆盖（面板本来也没有可比对的快照）；② 只有你明确点「仍要保存」才会跳过**一次**
  检测，插件不会替你选，也不会永久关掉这道闸门。

## 故障排查

| 现象 | 原因 / 处理 |
| --- | --- |
| 面板提示「连接思源超时」 | 内核没起、地址写错，或防火墙挡了 6806 端口。先在浏览器打开 `http://<地址>:6806` 验证 |
| 「思源内核返回错误：…」 | token 不对或没填。核对 设置 → 关于 → API token |
| `ECONNREFUSED` | 端口不通：Docker 没做 `-p 6806:6806`，或 IP 变了 |
| 面板空白 / 无入口 | 浏览器端插件没加载：确认 `dsh.client.platform = "web"` 且已重启 DSH Web |
| 保存后块 ID 变了 | 只可能来自插件之外的写入（例如思源端整篇覆盖）；用备份目录里的快照回滚 |
| 编辑器里图片显示「图未找到」 | 资源路径不对或内核里已没有这个文件：点卡片「显示源码」核对 `assets/…` 与思源里一致，再到思源确认该图还在 |
| 插图提示「上传接口没有返回 JSON」 | 宿主路由没就绪：**重启 DSH**（`lib/index.js` 的改动不随页面刷新重载，只有浏览器半边才热替换） |
| 图片显示但宽度不生效 | 宽度只认 `{: style="width: …px" }` 这一种行内属性，且值必须是 `px`/`%`/`em`/`rem`；其它写法会被忽略 |
| 备份找不到 | 看 `%USERPROFILE%\.dsh\siyuan-backups`；文件夹不存在说明从未成功保存过 |

## 路由契约（Host 半边）

统一挂在 `ctx.webServer` 的 `/siyuan` 前缀下，全部返回 JSON，不返回 HTML 错误页：

| Method | Path | 请求体 | 响应 |
| --- | --- | --- | --- |
| `GET` | `/siyuan/state` | — | `{ ok:true, value:{ baseUrl, hasToken, version, error? } }` |
| `POST` | `/siyuan/config` | `{ baseUrl, token }` | 同上（保存后立即探测版本） |
| `POST` | `/siyuan/api` | `{ path, payload }` | 成功：思源原始信封 `{ code, msg, data }`；失败：HTTP 200 + `{ ok:false, error:{ code, message } }` |
| `POST` | `/siyuan/backup` | `{ docId, title, kramdown }` | `{ ok:true, value:{ file } }` |
| `POST` | `/siyuan/context` | 编辑器快照 | `{ ok:true, value:{ accepted, updatedAt } }` |
| `POST` | `/siyuan/native` | `{ action: "open"\|"touch"\|"close"\|"forget-login", docId?, title?, parentOrigin?, id? }` | 创建、保活、释放原生会话或忘记本机登录；API token 与登录 Cookie 不返回浏览器 |
| `GET` | `/siyuan/layout` | — | `{ ok:true, value:{ layout } }` |
| `POST` | `/siyuan/layout` | 布局对象 | `{ ok:true, value:{ saved, updatedAt } }` |
| `GET` | `/siyuan/memory` | — （`?view=entries\|handoff\|checkup`） | `{ ok:true, value:{…} }` |
| `POST` | `/siyuan/memory` | `{ action, id }` | `{ ok:true, value:{…} }` |
| `POST` | `/siyuan/asset/upload` | **multipart**：`assetsDirPath` + `file[]` | 成功：思源原始信封 `{ code, msg, data:{ succMap, succFiles } }`；上限 32 MB（超限 413） |
| `GET` | `/siyuan/asset` | — （`?path=assets%2Fxxx.png`） | 图片二进制 + `Content-Type`/`ETag`；`If-None-Match` 命中回 304；非法路径 400；取不到 404 |

`/siyuan/api` 只放行以 `/api/` 开头的路径（禁止绝对 URL、`..`、查询串），防止被当成 SSRF 跳板。

`/siyuan/asset` 与 `/siyuan/asset/upload` 是图片功能的通道，各有一条硬约束：

- **为什么图片必须经宿主**：内核的 `/assets/<name>` 在没有 token 时不是 401，而是回一张
  SPA 首页（HTTP 200 + `text/html`，实测 3.8.3）。所以浏览器直接 `<img src="…/assets/x.png">`
  只能得到破图。宿主带 token 取回二进制再回传，token 全程不进浏览器。
- **取图只放行 `assets/` 前缀**：禁 `..`、`//`、`\`、`?`、`#`、`:`、空白与控制字符（`isServableAssetPath`），
  文档、笔记本配置、工作空间本身都够不到。
- **上传是原样字节流转发**：宿主不解析 multipart（boundary 一起转发），
  校验 `Content-Type` 前缀为 `multipart/form-data`，request body 上限 32 MB。
