# 档位跨模型保持只在「上游自动重置」时补正

在 composer 里换模型时，客户端提交的选择自带目标模型的默认档位（`ModelSelect` 把 `model.reasoning.defaultEffort` 塞进 selection），于是「我刚调到 max，换个模型又变回 high」成为最烦人的一处细节。

可选的干预点只有一个：选择提交之后。上游没有给「提交前」的钩子——`agent/pre-step` 的 payload 在 waterfall 之前已固定，`agent/request` 会因与 step selection 不一致而抛错，模型选择器本身是官方客户端包里的内部实现。

所以本插件在**选择落库之后**做一次幂等补正：观察会话的 `model/selection`，当且仅当「新提交的档位正好等于目标模型的默认档」且「该会话上一档被目标模型支持」时，追加一次修正过的 `model/selection`。

## Considered Options

- **一律保持**：只要上一档被支持就强行沿用。会把「我换个模型就是想用它的默认档」也一起改掉，用户无法表达"我要默认"。
- **只同 provider 内保持**：口子最小，但跨网关/A-B 两家里来回切正是最常见的场景，等于功能没做。
- **不做**：痛点留着（否决）。
- **只在自动重置时补正 + 跨 provider 适用**（采纳）：只在用户没有表达意图时出手。

## Consequences

- 判定需要目标模型的档位能力：用 `ctx.llm.resolveModelInfo(provider, model)` 取 `reasoning.efforts` 与 `defaultEffort`，不自己维护档位表。
- 补正必须**幂等且防循环**：同一次切换只补一次（以「会话 + 目标选择 + 上一档」为键去重），补正后若结果仍等于默认档则放弃并记一条 warn，不再重试。
  - **2026-11-19 勘误**：后半句从未实现。实际行为是判定不成立即静默返回，只有 `agent.model.select()` 抛错才记 warn（`lib/hooks.js:141-155`）。另：去重键不含"目标档位"、`corrected` 集合在 `installHooks` 闭包内，因此**不能**再加第二个监听同一事件的规则（见 ADR 0009 第 5 条）。
- 宿主侧监听 `session/event` 并在**微任务里**追加修正事件，不在事件分发栈内同步 append。
- 这个行为改写上游提交流程，因此**单独给一个开关**（默认开）：关掉即回到 DSH 原生行为，不需要卸载插件。
- 若补正在真实使用中出现抖动（菜单闪一下、事件重复），退路是"客户端在投影变化后重提交一次"的等价实现；两条路都不碰 asar。
