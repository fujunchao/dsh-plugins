# 工作区顺序靠改写宿主持久顺序实现，而不是接管侧边栏渲染

侧边栏的分组顺序完全来自宿主持久化的 `workspaceIds`，客户端只是原样渲染；插件没有任何"只改渲染顺序"的钩子。要做到"最近工作的项目在最上面"，只有两条路：接管整个 `sidebar.workspaces` 席位自己重画（搜索、拖拽、对话框、多语言全在里面，重且随 DSH 升级必坏），或者直接改写持久顺序（一次 `insertBefore`，与拖拽排序走同一条 `domain/changed → follow` 通道，UI 零改动、多窗口自动一致）。选了后者。

## Considered Options

- **客户端接管 `sidebar.workspaces`**：渲染层唯一能干预的位置，代价是复制 60KB+ 的分组逻辑，且 DSH 每次升级都可能失效。
- **读写一份独立的活动记录，只在 UI 侧叠加**：没有渲染钩子，叠加无从落地。
- **改写持久顺序**：实现最小，天然与拖拽、多窗口、下次启动一致；代价是自动排序会覆盖手动拖拽的结果。

## Consequences

- 自动模式下，用户手动拖拽的结果会在下一次"会话活动"或下一次启动时被重排覆盖。为此提供 `manual` 开关：切到手动后插件完全不碰顺序。
- 顺序是全局的：多窗口共享同一份持久顺序，一个窗口里的活动会改变另一个窗口的排列。
- 顺序变化会写 `workspace.json`；只有顺序真的改变时才写（`insertBefore` 自带幂等短路）。
