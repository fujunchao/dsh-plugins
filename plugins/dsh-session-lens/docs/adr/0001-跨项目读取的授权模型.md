# 跨项目会话读取：并存一套显式授权的工具，而不是放宽官方工具的授权

官方的模型可见会话工具按 `cwd` 字符串严格相等授权，所以在本项目的对话里读不到别的项目；而读取权限本身并不缺——人侧的 `@` 提及早就能跨工作区取快照，`ctx.sessionQuery` 也从不过滤 `cwd`，连沙箱都只管写不管读。因此我们**不修改也不 fork** `@deepseek-ai/dsh-tool-session-query`，而是新增独立 Host 插件 `dsh-session-lens`，注册 `session_projects` / `session_find` / `session_read` 三个工具与官方五件套并存；默认作用域仍是调用方工作区，跨区必须显式写 `scope: "all"`。这是因为“跨项目”要的是**意图可见**而不是**权限收紧**：装一道 bash 本来就能绕过的门只是安全剧场，而一个在 transcript 里看得见的 `scope: "all"` 才真正阻止“模型闲逛着把无关项目塞进上下文”。

## Considered Options

- **顶替官方五件套**：语义面最干净，但要把表层折叠、replacement 链、子会话血缘、无 id 边界标记重做一遍——拿手写版替换一个打磨过的包，v1 风险不成比例。
- **把官方包整包拷进插件、只改 `workspace-access.ts`**：代码量最小、行为 100% 一致，但 DSH 每次升级都要重对一次 diff，等于把一个内置件变成私有 fork。
- **白名单 / 首次跨区弹确认**：可被 bash 绕过，维护成本随项目数线性增长（本机 29 个注册项目），且与“一切以用户体验为最优先”冲突。
- **默认全开、不做显式参数**：能力上等价（反正能读到），但模型每次跨区都无声发生，污染上下文时人无法归因。

## Consequences

- 工具列表里会同时存在两套会话工具，前缀 token 增加，模型存在选错的可能；缓解手段是让**描述第一句就是可判定的边界**（“caller workspace only” vs “every project on this machine”），而不是靠名字前缀。
- 升级风险集中在 `ctx.sessionQuery` 这个公共 API 上，而不是私有 fork 的内部实现——API 变了会在编译期暴露。
- 配套三道**软闸门**（都不是安全边界，都是防意外）：外来内容用来源围栏+转义而不是道德警告；秘密默认脱敏并保留类型与长度；发现默认排除占半数的子会话。
- `session_read` 永远只读：不 resume、不 fork、不改名、不删除、不触发迁移发布。
