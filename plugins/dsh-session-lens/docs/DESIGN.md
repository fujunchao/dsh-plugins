# dsh-session-lens 设计

## 一句话

在**任意一个会话**里，让**模型**能按内容找到这台机器上任何项目的过去会话，并按“步”读到当时的原文；默认只看本工作区，跨项目必须显式，读到的东西只读、带来源、默认脱敏。

## 模块地图

| 文件 | 职责 |
|---|---|
| `lib/index.js` | 插件入口：注入声明、提示词段落、三个工具注册 |
| `lib/tools.js` | 工具描述与参数 schema（手写标准 JSON Schema，不导入 `@deepseek-ai/*`） |
| `lib/config.js` | 配置归一化（区间收口，不抛异常——配置错不该让工具消失） |
| `lib/caller.js` | 调用方身份、会话 id 解析、`dsh-session:` 规范 URI |
| `lib/projects.js` | 注册项目 vs cwd 桶的合并、目录与会话列表渲染 |
| `lib/find.js` | 跨区检索：作用域过滤、子会话过滤、命中带步号 |
| `lib/read.js` | 四种阅读模式、步区间、预算截断与续读 |
| `lib/outline.js` | 大纲的粒度阶梯（步 → 叙述段 → 轮次） |
| `lib/steps.js` | 步/轮次映射与区间计算 |
| `lib/render.js` | 内容块渲染、边注、围栏、转义、时间格式 |
| `lib/redact.js` | 值级秘密脱敏（保留类型与长度） |
| `lib/budget.js` | 字节预算与裁剪 |

纯函数与 I/O 分开：除 `index/read/find/projects` 之外全部无副作用，`node --test` 可直接跑。

## 两次被真实数据推翻的设计

设计是在 grill 阶段定的，但两处**只有量了数据才发现问题**。两次都保留了原意图（先定位再精读），只换了单位。

### 一、轮次不能当导航单位

原设计：大纲一轮一行、`from`/`to` 是轮次。

实测（`~/.dsh/sessions`）：

| 桶 | 会话 | 轮次合计 | 步合计 | 单会话最大步数 |
|---|---|---|---|---|
| cz | 48 | 212 | 7,174 | **1,034** |
| zcode2api-plus | 101 | 231 | 8,246 | 565 |
| dh | 9 | 9（**每会话 1 轮**） | 347 | 83 |

turn 是 **agent 处理周期**，不是人提问的单位：一轮平均 34 步，最长上千步；dh 那 9 个会话全部只有 1 轮。按轮切对大会话等于没有导航。

### 二、“一条人类消息一段”也不行

第二次尝试把段定义为“一条人类用户消息开启的一段”。中位数实测是 **1 条/会话**——因为 `user/message` 里绝大多数是注入的 runtime-context / skill-catalog / time-context（`source.kind` 各不相同），真正的人话很少。

### 结论：步是唯一可行的地址

`step`（一次模型调用 + 它的工具批次）是日志里唯一既足够细（中位数 97）又机械无歧义的边界。于是：

- **地址 = 步号**（`from`/`to`/`after_seq`）；
- **大纲行粒度自适应**：一行一步 → 一行一叙述段 → 一行一轮，取第一个能塞进 `maxOutlineLines` 的；
- 超预算的行标 `需续读`；
- 下钻姿势：按轮顶层地图 → 某轮内可读段落 → 读那一段正文。

### 三、大纲必须从原始日志构建，不能从表层

真机第一次跑大纲时，一个 1,034 步的会话只产出了 `t7–t17`。原因是**表层是折叠后的当前模型历史**：那个会话被压缩过，压缩点之前的历史已被 replacement 遮蔽，表层里根本没有那些事件（本地 fixture 的表层近似不做折叠，所以离线测试看不出来）。

修正：`outline` 与 `raw` 走 `readSession`（完整原始日志），`text` / `surface` 走 `readSurface`（“当时那个模型看到了什么”）。同一会话第二次跑，大纲覆盖 `t0–t17` 全部 18 行。

## 预算与续读

- 单次 `session_read` 默认 64 KiB（UTF-8 字节，不是字符——中文一字三字节，按字符算会低估两三倍）；
- 裁剪以**事件**为单位：半个事件留着会让续读指针无法精确；
- 续读参数是 `from=<下一块所在的步>` + `after_seq=<已发出的最后一个 seq>`，两者配合可精确续读而不重复；
- 整段装不下时**先给大纲**，而不是硬塞一个被截断的正文。

## 授权与内容卫生

| 决策 | 理由 |
|---|---|
| 默认 `scope: "workspace"`，跨区显式 `"all"` | 读取权限本来就不设防（沙箱只管写），这道门是**意图可见性**，不是安全边界 |
| 与官方五件套并存，不顶替、不 fork | 升级风险落在 `ctx.sessionQuery` 公共 API 上，而不是私有补丁 |
| 来源围栏 + `<` 转义 | 源文本伪造不出围栏、工具结果或下一条消息；`ref` 可粘贴成 `@` 引用 |
| 不说道德警告 | 内容类型与本工作区一致，说教只会让模型对所有材料打折扣 |
| 秘密默认打码、显式 `include_secrets` 放行 | 防的是秘密自己流进笔记/记忆/git，不是防模型 |
| 子会话默认不进发现结果 | 实测占会话总数一半（173/343），默认包含会让搜索结果一半是噪音 |

## 验证

见 `README.md` 的“开发与测试”与“真机验收”。要点：

- 80 条 `node --test`，含真实会话日志 fixture；
- 真实预演：cz 最大会话（1,034 步 / 6,808 事件）→ 顶层大纲 18 行（`t0–t17`），下钻 `from=614,to=758` 得到 30 余行可读段落（每行 15–45 KB）；
- **脱敏的漏洞只能靠真机抓**：单元测试样本里没有 `Authorization: Token demo-7f3a91` 与散文 `token demo-7f3a91` 这两种写法，第一版规则放过了它们；补 `auth-token`（含 Token/Bearer/Basic/Digest/ApiKey scheme）与“散文 secret 词 + 像凭据的值（含数字或 ≥24 字符）”两条规则后打码成立。同时加了 `looksSecretValue` 守卫，避免把 `token generation`、`token budget` 这类普通词组误伤；
- 只读复核：`~/.dsh/sessions` 344 个文件前后对比，只有本会话自己的日志在增长。

## 待定

- `raw` 层的续读目前也走步区间；如果将来需要按 seq 精确取证，可以加 `seq_from`/`seq_to`；
- 归档（`workspaceRegistry.archiveSession`）与回收站（`dsh-session-vault`）目前**不区分**：工具按“磁盘上存在”算。若将来要让“归档=不可读”，需要接注册表的归档集合；
- 跨 profile（不同 `DSH_HOME`）的会话不在可见范围；当前所有 profile 共用 `~/.dsh/sessions`，因此未暴露这个问题。
